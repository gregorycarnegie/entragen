# common

Pure-Rust logic behind [entragen](../README.md): file parsing and the two
generators. No `wasm-bindgen`, no DOM, no I/O — everything takes bytes and
returns values, which is what makes it testable on the host toolchain while the
`app` crate can only be built for `wasm32-unknown-unknown`.

```bash
cargo test -p common
```

## Entry point

`parse_any(bytes, required) -> Result<ParsedData, ParseError>` is the only way
in. It picks the format from the file's leading bytes rather than its name:

| Leading bytes | Handled as |
| --- | --- |
| `PK\x03\x04` | Workbook — `.xlsx`, `.xlsm`, `.xlsb`, `.ods` (via `calamine`) |
| `D0 CF 11 E0` | Pre-2007 `.xls` — **refused**, with a prompt to re-save |
| anything else | Delimited text (`.csv`, via the `csv` crate) |

Legacy `.xls` is refused rather than parsed: `calamine` can read it, but the
format is long superseded and carries the legacy macro attack surface, so the
error tells the user to save as `.xlsx` or `.ods` instead.

`required` names the columns the caller cannot work without. Missing ones fail
here, so the generators can index by column with `expect("validated by parser")`
rather than threading `Option` through every row.

The format-specific parsers (`csv_parser`, `spreadsheet`) are `pub(crate)` on
purpose. Routing everything through `parse_any` keeps the `.xls` policy in one
place instead of depending on which parser a caller happens to reach for.

## Generators

Both take `ParsedData` and return a result struct holding the generated files
plus the numbers the UI reports.

- **`house_teams::process`** — matches Bromcom students to Entra IDs by email,
  then groups them by house and year. Groups are keyed on the **raw**
  `(house, year)` pair, not the sanitized filename: `"Red House"` and
  `"Red/House"` both sanitize to `Red_House`, and keying on that would silently
  merge two houses into one group. Filenames that still collide get a numeric
  suffix.
- **`class_distribution::process`** — joins the emails export, the class list
  and the Entra export by admission number, filters by class tag, and emits
  either one combined file or one per year group.

Member IDs are sorted in every output path, so the same input always produces
byte-identical files.

## Layout

| File | What it holds |
| --- | --- |
| `lib.rs` | `parse_any` dispatch and the shared header validation |
| `csv_parser.rs` | Delimited text |
| `spreadsheet.rs` | Zip-based workbooks |
| `house_teams.rs` | House × year generator |
| `class_distribution.rs` | Class-tag generator |
| `types.rs` | `ParsedData` and the result structs |
| `errors.rs` | `ParseError`, `ProcessError` |

## Tests

Unit tests live beside the code they cover. Workbook fixtures are in
`fixtures/`, generated by `fixtures/mkxlsx.py` — minimal OOXML and ODF written
with nothing but the Python standard library, so there is no `openpyxl` to
install and no committed binary you cannot reproduce. Edit the row tables in
that script and re-run it; never hand-edit the `.xlsx` or `.ods`.

`rstest` covers named input cases for parsers, column lookup, filename
sanitization, and matching/year-group rules. `proptest` checks Unicode CSV
round trips, tag sets, safe filename components, and generator counts,
deduplication, membership, and row-order independence. Both are dev dependencies.
Property tests run with the normal test command above; to increase generated
cases, set `PROPTEST_CASES` (for example, `PROPTEST_CASES=1024 cargo test -p common`
on Unix, or `$env:PROPTEST_CASES=1024; cargo test -p common` in PowerShell).
Commit any `common/proptest-regressions/` files produced by a failing property
alongside its fix so the minimized counterexample is replayed in later runs.

Test quality is measured with `cargo-mutants` rather than line coverage; see
`.claude/skills/run-mutants/SKILL.md` for the current baseline and the fixture
rules that keep it there.
